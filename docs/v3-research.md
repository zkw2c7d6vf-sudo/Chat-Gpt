# Orbit V3 research and implementation decisions

Researched **October 25, 2026**. Official documentation below was fetched successfully over verified HTTPS during this build. These are documented capability findings, not verification against Joseph’s media files, paid streaming accounts, or an actual DoorDash order.

## Personal media center

**Decision:** a separate Media tab with Movies, TV, and Photos, using user-selected local files and an HTML video/image viewer. Browser-supported files can play inside Orbit; paid streaming-service pages should remain external links rather than pretending to be playable video sources.

| Finding                                                                                                                                                                                                                                                                    | Consequence for Orbit                                                                                                                                                                                                                                                                                                                                                                           |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The [HTML video element](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video) provides controls, playback events, fullscreen-related browser behavior, and WebVTT caption tracks.                                                                   | Use native controls for accessible, dependable playback. Save progress from media events; support pause/resume and clear playback errors. Only show optional picture-in-picture controls when the browser supports them.                                                                                                                                                                        |
| MDN’s [Web video codec guide](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Video_codecs) distinguishes codecs from containers and describes browser/device-specific support.                                                                          | A filename ending in `.mp4` or `.mov` does not guarantee playback. MP4 with common H.264/AAC encoding is a sensible compatibility target, with WebM where supported. Do not promise MKV, HEVC, or every downloaded video will play. If decoding fails, explain that a compatible encoding/browser or external player is needed; do not silently mark the title played.                          |
| The [File API](https://developer.mozilla.org/en-US/docs/Web/API/File_API) exposes files explicitly supplied by the user, including metadata and contents.                                                                                                                  | An import picker does not grant background access to the entire Mac. Local selection must be explicit. Do not invent a server filesystem path from the browser file name. Keep object URLs scoped to the active viewer and revoke them when released.                                                                                                                                           |
| [Storage quotas and eviction criteria](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria) describes origin-scoped IndexedDB, browser-managed quota, storage-pressure eviction, and optional `navigator.storage.persist()`. | Keep metadata out of large localStorage payloads. If media blobs are retained in IndexedDB, describe that they consume local browser storage, handle quota failures, and retain originals separately. Storage is browser/origin-specific and can disappear when site data is cleared; a persistence request is not guaranteed. A metadata-only backup cannot restore missing video/photo bytes. |

A built-in HTML player is feasible for compatible personal files. No source reviewed establishes general access to Netflix/Disney+/other DRM catalogs through a generic player; Orbit should not bypass provider authentication, licensing, or DRM.

## DoorDash: what can work tonight

**Decision:** provide an order card with an optional official tracking link, user-entered restaurant/ETA, and explicitly manual status controls. The live map opens in DoorDash. Never display a simulated Dasher position or imply the ETA/status is provider-synced.

- [DoorDash Drive API reference](https://developer.doordash.com/en-US/api/drive/) describes **Get Delivery** as obtaining the status/details of a delivery **“that you created.”** Its response includes `tracking_url`, and webhooks can deliver updates for integrated deliveries. This is evidence for a partner-created delivery integration, not a documented lookup API for arbitrary personal Marketplace orders.
- [About DoorDash Drive](https://developer.doordash.com/en-US/docs/drive/overview/about_drive) describes delivering a business’s goods using DoorDash logistics. The page currently says Drive APIs are **limited access** and prospective partners can apply through the Developer Portal.
- [Marketplace overview](https://developer.doordash.com/en-US/docs/marketplace/overview/) also says **limited access**. Its described functions manage partners’ menu, store, and order data. No general consumer-account tracking API was found in the official documentation reviewed.
- [Embedding delivery tracking page](https://developer.doordash.com/en-US/docs/drive/reference/embedding_delivery_tracking) documents embedding a DoorDash tracking page in an ordering application, using a `delivery_tracking_url` obtained from fulfillment APIs/webhooks. It explicitly asks implementers to contact DoorDash’s team to embed tracking. Thus an embedded partner route exists, but it has not been established for Joseph’s ordinary consumer order or approved for Orbit. Do not describe embedding as universally impossible, and do not promise it works merely by putting a consumer order page in an iframe.
- [Drive integration requirements](https://developer.doordash.com/en-US/docs/drive/overview/integration_requirements) reinforces partner onboarding. This is disproportionate to a simple personal dashboard order card unless DoorDash later provides an appropriate authorized route.

For V3, store a pasted HTTPS link locally and open it in a new tab with `noopener noreferrer`. Accept only recognized DoorDash hosts and official `drd.sh` short links; reject lookalike or non-HTTPS links. Tracking URLs may expose private order information: keep them out of assistant context, public screenshots, and portable backups by default. Orbit should never request a DoorDash password, session cookie, or an exported browser login to scrape tracking.

The official consumer help URL was reachable, but this environment received a JavaScript page shell without the article body; it was not used as evidence for an API capability. Some guessed older developer URLs returned 404; the successful source links above are the actual pages reviewed.

## Three additions that fit Joseph’s dashboard

1. **Continue watching:** a small dashboard entry with the title and real saved progress, resuming the built-in player. Useful because the media center should not require navigating and seeking every time. Do not turn a failed playback attempt into saved progress or imply that an unavailable local file is ready to stream.
2. **Tonight’s queue:** a short ordered watch-next list for movies and episodes, placed near the dinner card. It connects the media side project with tonight’s DoorDash plan without inventing personal habits, requiring recommendations APIs, or adding unrelated services. Queue entries can be added, reordered, removed, and marked watched.
3. **Portable backup/restore:** export/import the dashboard’s local tasks, notes, watchlist/queue, and player progress with schema validation. Exclude OAuth tokens, API keys, private calendar URLs, private delivery tracking links, and media bytes. Explain missing-file reattachment clearly and validate an import before changing existing state. This directly addresses the ZIP upgrade workflow and the risk of browser-local storage loss.

These additions remain local and reversible. They do not create accounts, place orders, message anyone, or imply automatic access to future ChatGPT conversations. Joseph’s separate website project remains out of scope.
