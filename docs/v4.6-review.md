## Confirmed Shopping defect and repair

An isolated worktree at baseline `970f61c`, served on port 5174, reproduced the crash. After Shopping mounts, make `Storage.setItem` throw `QuotaExceededError` only for `orbit-shopping-*`, then submit a nonempty saved search. The baseline raises an uncaught exception and unmounts the application. Reproduction command:

```
ORBIT_URL=http://127.0.0.1:5174 ORBIT_EXPECT_CRASH=1 node tests/shopping-storage.e2e.mjs
```

Draft PR #5 (`0737f819`) correctly identifies unguarded storage writes as a crash risk. The 4.6 implementation incorporates its guard/warning intent and adds retry and recovery coverage. It does not merge the unverified branch or claim that storage is the only possible cause of the Mac-reported crash.

Shopping no longer writes untouched data on mount. Changed searches/offers use guarded persistence; failed writes leave the current working state available, display a warning and expose **Retry saving shopping**. A successful retry persists the pending records. The regression exercises failures for both record types, recovery and reload, blank and duplicate searches, encoded retailer links, a missing `crypto.randomUUID`, and a failed shopping API. Unsaved in-memory changes still require a successful retry before closing or refreshing the tab.
