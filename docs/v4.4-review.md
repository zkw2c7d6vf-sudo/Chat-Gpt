# Orbit v4.4 — refinement review

This pass reviews the existing v4.3 experience for clarity, reliability, and duplicated effort. It keeps Orbit local-first and avoids adding services that need paid APIs or invented personal data.

## Seven review passes

1. **Home and hierarchy:** Keep the Today view focused on the next event, tasks, and the existing daily tools. Secondary destinations remain in navigation instead of being repeated as large cards.
2. **Calendar setup:** Keep Google Calendar and private ICS as distinct ways to supply events. ICS imports are snapshots; a private feed refreshes; Google is live. The existing labels and connection flow communicate those differences.
3. **Google recovery:** Google API failures were collapsed into a generic 403 message. Now Orbit distinguishes a disabled API from missing consent scopes, names Calendar/Gmail/Drive, and gives a different next step for each. Other Google services that succeed still populate.
4. **Tasks and capture:** Preserve one task list and one capture flow as the source of truth. Keep completion, quick entry, and backup behavior intact; avoid adding duplicate task panels.
5. **Weather and settings:** Keep Buffalo as the default, the seven-day forecast on Home, and location/unit controls in settings. Do not recreate a separate weather destination.
6. **Shopping and media:** Keep coverage honest: saved comparison listings and catalog discovery are not universal retailer scraping or DRM streaming. External services stay clearly identified as links.
7. **Accessibility and resilience:** Retain keyboard access, reduced-motion support, responsive layouts, local backup/restore, and clear empty states. Re-run unit/API, production build, and browser checks after the server change.

## Change in this pass

When a Google request returns 403, Orbit reads Google’s structured error reason. `accessNotConfigured` points to the named API and the OAuth client’s Cloud project. `insufficientPermissions` points to disconnecting and reconnecting Google to renew consent. Unknown 403 responses name the affected service and preserve a useful project/permission diagnostic. Error responses remain isolated to the affected panel; successful Calendar, Gmail, Drive, and Spotify data continue to render.

## User action still needed for Google

The app cannot enable APIs or approve OAuth scopes in the user's Google project. If Orbit reports a disabled API, enable that named API in the same Cloud project as the OAuth client. If it reports missing permissions, disconnect and reconnect Google in Orbit and approve the requested access. A private ICS feed remains an alternative for calendar-only use.

## Test build follow-up

Calendar and Inbox now identify service failures instead of presenting them as an empty schedule or caught-up inbox. The updater test compares the installed version against the release manifest so future releases do not fail on an old hard-coded version. The package includes startup instructions and a production build, with no credentials or personal storage.
